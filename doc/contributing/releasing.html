    Releasing

    Versioning

    We follow Semantic Versioning. The version X.Y.Z indicates:

    • X is the major version (backward-incompatible changes to the API, the supported target frameworks or the major version of a runtime dependency),
    • Y is the minor version (backward-compatible new features), and
    • Z is the patch version (backward-compatible bug fixes).

    Release to NuGet

    To release a new version, publish a GitHub release on main with the tag vX.Y.Z (e.g., v2.0.0).

    Publishing the release triggers the workflow publish-to-nuget.yml in .github/workflows. The workflow takes the package version from the tag, builds the package and pushes it to NuGet using trusted publishing, so no API key is needed. The <Version> in AasCore.Aas3.Package.csproj is only used for local builds.

    Building the Package Locally

    To build the package locally, invoke:

    dotnet pack -c Release -o artefacts src/AasCore.Aas3.Package

    In cases of substantial changes to the solution, you need to delete bin and obj subdirectories beneath src as dotnet will not do that for you. We provide a shallow script to save you a couple of keystrokes:

    .\src\RemoveBinAndObj.ps1
